# Публикация базы на moleculai.ru

Источник материалов — `outputs/knowledge-base/*.html`. Адрес сайта — `https://moleculai.ru/knowledge-base`; CMS — `https://cms.moleculai.ru`. Ветка `main` в GitHub сохраняет исходники и статическую версию.

`publish_kb.py` преобразует материалы в компоненты CMS: Markdown, запросы с копированием, карточки, изображения/видео и раскрываемые ответы. 27 заданий остаются отдельными страницами. Каждая модель и роль имеет свою карточку. Аудиофайлы открываются по прямой ссылке на CMS. Возможности интерактивного теста и переносимого прогресса есть только в статической версии.

## Порядок

Используйте Python с `lxml` из рабочего окружения. `work/cms-publication/access.md` — локальный файл доступа, исключённый из Git; его содержимое никогда не выводится.

```sh
python3 scripts/publish_kb.py --plan
python3 scripts/publish_kb.py --publish dev --access-file work/cms-publication/access.md --only SLUG
python3 scripts/publish_kb.py --publish prod --access-file work/cms-publication/access.md
python3 scripts/publish_kb.py --verify prod --access-file work/cms-publication/access.md
```

`--only` принимает несколько существующих или подготовленных адресов; для новой страницы включите также новый родительский раздел. Без `--only` публикуется вся база. При первом запуске на новом компьютере добавьте `--access-file` к `--plan`, чтобы получить исходный снимок CMS; режим `--publish` получает свежий снимок автоматически.

Скрипт сохраняет резервную копию опубликованных страниц перед записью. После публикации он повторно читает CMS и сравнивает заголовки, связи, видимость, все блоки и полные запросы с экспортом. Публикация выполняется только с явным `status=published`, в локали `ru`. Идентификаторы документов определяются отдельно для каждого окружения.

Неизменённые страницы пропускаются по контрольной сумме. Медиа повторно не загружаются, если сохранилась запись о совпадающем файле; при первом переносе повторно используются уникальные совпадения имени и размера из библиотеки CMS. Старые страницы не удаляются: объединённые инструкции скрываются из меню и ведут на актуальный материал.

`kb-routes.json` хранит стабильные соответствия локальных файлов, моделей и ролей адресам сайта, а также перечень разделов, которыми управляет скрипт. Новые страницы, добавленные другим редактором прямо в CMS, он не перезаписывает. Резервные копии, экспорт, идентификаторы загрузок, отчёты и ключи находятся только в `work/cms-publication/`.

## Пользовательские руководства

`build_user_guides.py` добавляет подробный пользовательский слой к существующей HTML-базе. Собственные материалы находятся в `user_guide_content.py`, исходные карточки в `user-guide-catalog.json`. Повторная сборка не дублирует примеры. Скрипт сохраняет старые адреса, якоря, запросы заданий и идентификаторы прогресса; не обращается к сервисам и не запускает генерации.

```sh
python3 scripts/build_user_guides.py
python3 scripts/verify_user_guides.py
```

Проверка требует `lxml`, Git и локальный исходный снимок CMS в `work/cms-publication/prod-full.json`. Старые ограничения объёма коротких карточек не применяются к подробным руководствам новой редакции. Существующая проверка JavaScript-прогресса остаётся обязательной при изменении соответствующего кода.

`user-guide-routes.json` назначает раздел только новым руководствам. Существующие CMS-связи сохраняются. Поле `data-mode` у отдельного запроса определяет инструмент при экспорте: `text`, `image`, `video` или `audio`. Это нужно для смешанных задач, например текстовых подписей, фотографии товара и анимации. Начальная CTA в CMS ведёт к первому чату, а практические бизнес-модули остаются отдельным маршрутом.

Перед сообщением об успехе откройте живой сайт: проверьте первое задание, раздел модуля, одну модель, изображение/видео и переходы. Успешный ответ CMS сам по себе не подтверждает отображение на сайте. Если запись или проверка прервалась, сначала прочитайте отчёт и свежую CMS; не удаляйте страницы и не повторяйте вслепую неизвестные загрузки.
